AI指南

所有游戏服务器的部署和运维问题，都推荐使用 AI 辅助。拥有终端和目标环境所需权限的 AI 助手可以阅读项目源码与文档，自动编译、部署和启动服务，并检查运行结果。

1. 提供可复现的上下文

开始前记录仓库和提交、操作系统、编译器、构建类型及客户端版本。把项目 README、构建说明，以及能复现问题的完整命令交给 AI。日志可以截取第一条错误前后的上下文，先删去凭据、数据库连接串和玩家信息。

git status --short
git rev-parse --short HEAD
git submodule status
cmake --version

只有项目使用 CMake 时才需要最后一项。项目已有的构建脚本和文档优先。

2. 编译与定位首个错误

  1. 让 AI 先读取项目构建说明，列出需要的依赖、生成器和目标。使用独立构建目录，在测试环境执行。
  2. 从第一个导致失败的错误着手。区分编译、链接、生成器配置和运行期依赖，随后再检查派生错误。
  3. 改动后使用相同环境和命令复跑。确认进程退出码和产物路径，并运行仓库现有测试。

已经确认项目采用 CMake 时的示例

cmake -S . -B build
cmake --build build --config Release --parallel 2

Visual Studio 等多配置生成器通过 --config Release 选择构建类型。Ninja 或 Makefiles 等单配置生成器通常在配置时指定 -DCMAKE_BUILD_TYPE=Release。构建参数以仓库文档为准。

可直接使用的任务描述

先读取当前仓库的构建说明。根据我的系统、提交和日志，
指出第一个失败步骤，引用对应文件或错误行。
给出范围最小的修复，并用原命令复跑。
报告退出码、产物路径和未完成的验证。

3. 部署并启动服务

把仓库路径、目标环境和验收条件交给 AI。让它按项目文档执行部署与启动，并用日志、监听端口和实际游戏连接验证服务。

可直接交给 AI 的部署任务

读取这个仓库的 README、构建与部署文档，确认当前版本和依赖。
在指定环境按项目文档编译、部署并启动服务。
检查进程、启动日志、监听端口和客户端能否连接。
报告实际执行的命令、所部署的版本和验证结果。

4. 维护、升级和回滚

  1. 把问题写成可观察的结果，例如“重连后角色仍在原地图”。记录程序版本、配置、数据库或存档版本。
  2. 让 AI 对照日志与代码列出证据。依次验证进程启动、账号登录、核心交互、保存及重连。
  3. 涉及数据库或存档更新，先备份并在隔离环境试恢复。把回滚所需的程序、数据和配置作为一组保存。
  4. 正式发布前人工确认变更范围。发布后复查日志、可用性和实际游戏流程。

可以让 AI 生成升级清单、整理失败日志、审阅差异。保留原始输出，才能区分编译通过、测试通过与线上验证。

5. 按项目验收

  • 魔兽世界。检查核心分支对应的客户端构建、数据文件及数据库更新，验证登录、选服和进图。
  • 云端千年。核对服务端、资源和客户端版本，分别验证 Windows 和安卓端的显示与登录。
  • 魔力宝贝。检查补丁与客户端版本，使用测试账号验证首次自动注册和再次登录。
  • 文字 MUD。区分 FluffOS 驱动构建和 LPC 脚本加载，分别验证登录、指令、存档与重连。
